**結論**

現在のプロジェクトにおける主な**課題・反省点**を、指定された構成でまとめます。  
**1\. サーバーの安定性とパフォーマンスの低下**

* **概要**: 本番環境のサーバー停止（500エラー）およびサイト全体の表示速度の低下。  
* **詳細**: サーバーのストレージ不足によるシステム停止や、特定のIP帯からの大量アクセス（ボット）によるCPU負荷の増大が確認されている。また、サイト全体の表示速度が遅いため、離脱率の増加も招いている。  
* **原因**: 72GBを超える巨大なバックアップファイルの残存、MySQLのbin\_logの肥大化。また、特定のボットによる1日40万〜50万件のアクセスや、未最適化のクエリ・画像処理が原因。  
* **影響**: ユーザーがサイトにアクセスできなくなる、広告経由のCV率が低下するなどの実害が発生している。  
* **対策**: 不要ファイルの削除、MySQLログの定期的監視と削除、Grafana等の監視ツールの導入。また、特定IPの遮断（Rate limit設定）やコード・クエリの最適化（15%の改善見込み）を進める。

**2\. 通知システムの信頼性不足（メール重複送信）**

* **概要**: スマート体入等の申し込み時に、通知メールが異常な数重複して送信される。  
* **詳細**: 会員がスマート体入を申し込む際、クライアントに最大15通の通知メールが届く事象が発生。  
* **原因**: 運営管理や店舗管理の複数のメールアドレス設定に対して個別にメールを送信するロジックに加え、システムが送信控えを都度生成している。また、ユーザーがボタンを連打することで複数回の申し込みとして処理されている。  
* **影響**: クライアント（店舗）へのスパム状態となり、運用への不信感や混乱を招く。  
* **対策**: 通知先ロジックの整理（重複送信の防止）、申し込みボタンのローディング処理の追加による連打防止。

**3\. 旧システムからのデータ移行とマッピング不備**

* **概要**: 既存の求人データにおける駅情報やエリア情報の消失・未反映。  
* **詳細**: 旧システムから移行した数千件の求人において、駅情報が空欄になる、あるいは管理画面で編集・保存すると鉄道会社や駅の情報が消えてしまう現象が発生。  
* **原因**: リファクタリング時に検索ロジックからテーブル結合（JOIN）が漏れたこと、およびデータ更新時のオフセット処理（chunk関数）の不備による更新漏れ。  
* **影響**: 既存店が情報の更新を正確に行えず、ユーザー側でも正しい検索結果が表示されない。  
* **対策**: `chunkById` へのロジック変更による確実なデータ更新、および消失したデータの再マッピング作業の実施。

**4\. 広告運用を阻害するURL設計**

* **概要**: 絞り込み検索後のURLパラメータが長すぎて広告配信ができない。  
* **詳細**: 複数エリアを選択した際の検索結果URLがMeta（旧Facebook）側の文字数制限を超え、エラーが発生している。  
* **原因**: URLパラメータに日本語の地域名や長い文字列がそのまま含まれており、数千文字に達しているため。  
* **影響**: Meta広告を通じた集客が不可能になり、マーケティング戦略に支障をきたしている。  
* **対策**: 検索結果ページのURL設計の抜本的な改修（パラメータの短縮化やID化など）。

**5\. プロジェクト管理上の反省点（仕様の不一致）**

* **概要**: 開発中およびテストフェーズにおける新規追加依頼（Change Request）の多発。  
* **詳細**: 全イシューのうち半数以上（約54.5%）が当初の設計にはない「新規追加依頼」であり、UI/UXの細かな調整が後手に回っている（会話履歴参照）。  
* **原因**: 当初の要件定義やデザインの確認不足、あるいは実運用に合わせた導線設計の詰めが甘かったこと。  
* **影響**: 開発工数の増大、および重大なバグ改修の遅延。  
* **対策**: 重大バグの修正を最優先事項としつつ、追加依頼についてはフェーズ2以降に回すなどのスコープ管理の徹底。

**6\. デザインガイドラインおよび共通スタイルの反映不足**

* **概要**: 全画面におけるフォント、マージン、角丸などのデザイン仕様の不統一。  
* **詳細**: ボタンの角丸（応募6px/その他4px）、線の太さ(2px)、フォントサイズ（10px/12pxへの引き上げ）などの基本ルールが多くの画面で適用漏れとなっている。また、特定の入力フォームやポップアップでのマージンがデザインデータと乖離している。  
* **原因**: 共通コンポーネントの定義が不十分なまま各機能の実装が進んだこと、およびフロントエンドの実装後のデザインチェック（検収）工程が機能していなかったこと。  
* **影響**: サイト全体の品質感の低下を招き、ユーザーに「未完成なサイト」という印象を与える。また、細かな修正依頼（Change Request）が全体の54%を超える要因となった。  
* **対策**: CSS変数の再定義と共通スタイルの徹底適用。デザインデータ（Figma/XD等）との突合チェックを必須化する。

**7\. スタッフ権限におけるデータ更新フローの考慮不足**

* **概要**: スタッフ権限（Role 3）による店舗情報の編集が、掲載の停止を招く運用上の不備。  
* **詳細**: スタッフが店舗情報を修正すると、管理者（Role 4）が「承諾」するまで掲載が落ちてしまう仕様になっていた。また、編集画面で「営業担当者」が未設定に戻るなどの挙動も発生。  
* **原因**: システム上の「公開フラグ」と「承認ステータス」の連動が強すぎ、承認待ちの状態を「非公開」と同一視して実装されていた。  
* **影響**: 代理店（スタッフ権限）が日常的な情報更新を行えず、店舗の集客機会を損失させる。  
* **対策**: 修正内容を一時保存テーブル（StoreEdit等）で管理し、承認されるまでは旧データで掲載を維持する「承認フローの分離」を実装する。

**8\. 検索順位ロジックの不整合（プラン優先度）**

* **概要**: 検索結果における掲載プラン（Z/フリー/ブロンズ〜ダイヤ）の表示順位およびランダム表示の不具合。  
* **詳細**: フリープランとZプランの順位が逆転したり、同一プラン内でのランダム表示が機能せず毎回同じ店舗が上位に来る事象が発生。また、「掲載終了＆公開継続」時の順位設定が正しく反映されていなかった。  
* **原因**: 複雑化したプラン体系（2025年版）に対するSQLのソートクエリの実装ミス、およびページネーション時のランダムシード保持の考慮漏れ。  
* **影響**: 有料プラン契約店舗からの不満、サイトの信頼性低下。  
* **対策**: プランごとの重み付け（Weight）の再定義と、プラン内ランダムソートロジックの厳格な適用。

**9\. エリア・沿線情報のマッピングとインポート不備**

* **概要**: 全国エリア展開に伴う、膨大な鉄道・駅データの反映漏れと不正確な紐付け。  
* **詳細**: 千葉県の駅が埼玉に表示される、特定の路線が重複・消失するなどのデータ不備が多発。旧システムからの移行時に駅名が空欄になる事象も確認された。  
* **原因**: データインポート用スクリプト（chunk処理）のバグにより、一部のレコードがスキップされていたこと、およびマスタデータの精査不足。  
* **影響**: 地方エリアでの検索が不可能になり、全国展開のマーケティング施策に致命的な支障をきたす。  
* **対策**: `chunkById` へのロジック変更による更新漏れ防止、および提供されたスプレッドシートに基づく全マスタデータの再インポートと整合性チェックの実施。

**10\. コンテンツエディタ（つぶやき・レポ）の機能反映不足**

* **概要**: つぶやき機能や体入レポにおける文字数カウントや改行仕様の不一致。  
* **詳細**: 絵文字が2文字分でカウントされる問題や、エディタ上での改行（Enter/Shift+Enter）がサイト側で正しく再現されない問題。  
* **原因**: 管理画面のCKEditor（リッチテキストエディタ）とフロント側のHTMLレンダリング/サニタイズ処理の仕様が統一されていなかった。  
* **影響**: 店舗が意図した通りの投稿ができず、情報の更新頻度が下がる原因となる。  
* **対策**: フロント・バック双方での文字カウントロジックの共通化、およびCSS（white-spaceプロパティ等）による改行再現の修正

## **1\. 機密構成ファイル（.env）と .git ディレクトリの漏洩**

| 重大度 | 重要 |
| :---- | :---: |

**影響範囲**

* アプリケーションキー（APP\_KEY）の漏洩

* データベース認証情報（DB\_USERNAME、DB\_PASSWORD）

* Google API 秘密情報（GOOGLE\_CLIENT\_SECRET、Refresh Token）

* ソースコード全体と Git 履歴の公開

*※ 旧システムでも同様の問題が発生する可能性があります。*

**リスク**

* セッション/クッキーの復号によるなりすまし

* データベースへの不正アクセス、ランサムウェア攻撃

* Google API の不正利用によるコスト増大・アカウント停止

* 技術的知財情報の流出による追加脆弱性の探索リスク

**原因**

* Nginx が隠しファイルへのアクセス制御を実装していない、.env が .gitignore に未登録。

**対策（短期）**

* php artisan key:generate で APP\_KEY 再生成

* Google の Secret と Refresh Token を無効化・再発行

* DB\_PASSWORD を即時変更

* Nginx で隠しファイルをブロック（location \~ /\\. { deny all; return 404; }）

* .env を .gitignore に追加し、履歴から削除（git rm \--cached .env）

* 6 週間にわたる活動期間中の不明な操作（データ抽出、バックドア設置）

**対策（短期）**

* マルウェアファイルを安全な外部ストレージへバックアップ後完全削除

* www ユーザーの crontab を全削除し、信頼できるタスクのみ再作成
