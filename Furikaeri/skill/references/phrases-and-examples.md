# 振り返りレポート 表現・フレーズ集

このファイルは振り返りレポートでよく使う日本語表現をまとめたリファレンスである。
SKILL.md と組み合わせて使用すること。

---

## 1. 課題・原因・影響・対策のフレーズパターン

### 課題（概要）の書き方
```
[カテゴリ名]の[不足/遅延/認識不足/未対応]
```
例：
- 仕様・要件の確認不足
- インフラ認識の齟齬
- テスト品質の未達
- SEO対策の遅延
- AI活用の不足

### 詳細（事象）の書き方パターン
```
[何が]を[誰が/何が]に[どうした]結果、[何が発生した]。
[何の]定義が不十分で、[後工程/実装後]に[手戻り/修正]が発生した。
```

### 原因の書き方（①②番号付き）
```
①[直接原因]: 〜が不十分だった / 〜を正しく把握できていなかった
②[構造的原因]: 〜の仕組みが存在しなかった / 〜の経験者がいなかった
```

### 影響の書き方
```
①[工数への影響]: 〜の作り直しにより大幅な工数が発生した
②[納期への影響]: 後続工程（〜、〜）に遅延が波及した
③[信頼への影響]: クライアント様の信頼低下につながった
```

### 対策の書き方
```
①[予防策]: 〜を事前に〜し、リスクを早期に特定する
②[プロセス整備]: 〜を書面（〜）で明確化し、合意を得てから実装を開始する
③[体制強化]: 〜のレビューで〜の意図を明確に共有する
```

## 2. よかった点のフレーズ

### 技術的成果
- 〜アーキテクチャにより、各レイヤーを独立して開発・デプロイできる体制を構築した
- 〜による〜で、パフォーマンスと精度が向上した
- 〜連携により、〜を自動化した
- 〜を活用した安全な〜基盤を構築した

### チームワーク
- 問題発生時の連携が素早く、メンバー全員で早期解決に向けて対応した（営業時間外・土日を含む）
- 困難な状況においても高いモチベーションを維持し、プロジェクト完遂に尽力した
- クライアント様からの積極的なフィードバック・サポートにより、問題解決を加速できた

### プロセス改善
- リリース後に運用面での振り返りを実施し、保守フェーズに向けた改善アクションを確立した
- 〜のプロセスを整備し、次フェーズに向けた知見を蓄積した

## 3. 次プロジェクトへの提言フレーズ

### 注意すべき点（よく使うパターン）
- リリース前には必ず〜（SEO設定/セキュリティ/非機能要件）を確認する
- 外部サービス連携はサンドボックス環境での事前検証を徹底する
- 技術選定は必ず書面（技術仕様書）で明確化し、クライアント様と合意を得てから実装を開始する
- 要件・仕様の認識齟齬を防ぐため、コーディング中の発見は「仕様確認ログ」として記録し、必ず合意を得てから実装する
- 品質基準（Acceptance Criteria）を事前に明文化し、セルフチェック・コードレビューを徹底する

### 協力体制（クライアントへの依頼表現）
- 重要なマイルストーン（設計レビュー・リリース前）では双方で確認体制を設けることを推奨します
- 技術的な意思決定は早期にご共有いただき、認識のずれを防ぐことが重要です
- 要件変更は必ずチケット化し、影響範囲と工数の見積もりを経て承認を得るプロセスを徹底します
- 問題発生時は早期にご共有いただき、協力して解決する体制を維持します

## 5. 実例：塾講師コネクトの課題表（参考）

このプロジェクト（Juku Teacher Connect、2025年6月〜12月）で発生した課題の記載例：

| 概要 | 詳細 | 原因 | 影響 | 対策 |
|------|------|------|------|------|
| 仕様・要件の確認不足 | 要件が曖昧なまま開発を進め、後工程で認識の齟齬が発生。境界値・エラーハンドリングの定義が不十分で実装後に手戻りが生じた | ①インプット情報が画面一覧・ワイヤーフレーム・Figmaのみで、短期間内に全ロジックの確認が困難だった②コーディング中に新たなロジックが発覚し、その場での仕様決定・変更が多発した | ①実装済み機能の仕様変更により大幅な修正工数が発生②品質・納期に影響 | ①コーディング開始前に業務ロジックの事前確認・質問を徹底する②コーディング中の仕様発見は「仕様確認ログ」として記録し、CLANE様と合意後に実装。口頭のやり取りは必ずチケット・メールに記録する |
| インフラ認識の齟齬 | クライアント側のインフラ要件（AWS CDK）を誤解し、AWS Copilotで構築を進めた結果、後工程での作り直しが発生した | ①クライアントの技術要件（AWS CDK）を正しく把握できていなかった②技術窓口担当者にAWS CDK/Copilotの十分な知見がなく、適切な合意が得られなかった | ①構築済みインフラの作り直しにより大幅な工数が発生②納期に影響し信頼低下③後続工程（デプロイ・テスト）に遅延が波及 | ①技術選定・要件は書面（技術仕様書）で明確化し、合意後に実装を開始する②不確実な技術領域はPoCを事前実施し、リスクを早期に特定する③設計レビューで技術選定の意図を明確に共有する |
