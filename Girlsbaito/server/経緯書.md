# 経緯書（セキュリティインシデント総合報告）

## プロジェクト: Girlsbaito | 報告作成日: 2026/05/22

**全体的な重大度: CRITICAL（緊急）**  
**現在のステータス: 対応中 & 修復中**

---

### I. エグゼクティブサマリー
- 発見時刻: 2026/05/21 13:49、access‑log の解析により検出。
- インシデント概要: 機密構成ファイル（`.env`、`.git`）およびシステムログ（`laravel.log`）が漏洩。さらに Production サーバ上でマルウェアが永続化していることが判明。
- 現在のステータス: マルウェアは一時的に停止。CPU、RAM、ネットワークは正常。機密ファイルは 2026/05/20 以降公開アクセスがブロックされている。
- 緊急リスク: 個人情報と機密鍵が漏洩。顧客データ保護と信頼回復のため、迅速な対応が必要。

---

### II. 根本原因分析 (Root Cause Analysis)

#### 1. データ移行時の情報漏洩
- **Migration 手順のクリーンアップ不足**: プロジェクト全体をコピーする際、`storage/logs/`（2022/10 以降のログ）も含めて新サーバへ転送。*一般的にサーバ移行時は全データをコピーする*。
- **Cleanup 手順の欠如**: 移行前に古いログ、バックアップ、機密 ZIP ファイルを削除・除外しなかった。

#### 2. 新環境導入時の技術的脆弱性
- **Apache → Nginx 移行が不完全**: 旧サーバの `.htaccess` と新サーバの Nginx 設定の両方が、隠しファイルやログへのアクセスを遮断するルールを無視。（設定が無く、攻撃に脆弱）
- **プロジェクト構成の不備**: `index.php` がルートディレクトリに置かれ、`.env`、`.git`、`storage/logs/` が公開可能な静的リソースとしてアクセス可能。

#### 3. プロセス・人的リソースの不足
- **セキュリティチェックリストの未整備**: Laravel を Nginx 上にデプロイする際の安全性確認ドキュメントがなく、Go‑live 前のセキュリティレビュー手順も未実施。（旧システムでも同様の問題が残っていた）
- **運用スキルの不足**: Laravel/Nginx の設定が旧システムのセキュリティ基準に依存し、実装後の実運用テストが行われていない。

---

### III. 詳細インシデント報告 & 脆弱性

#### 1. 機密構成ファイル (`.env`) と `.git` ディレクトリの漏洩
- **重大度**: CRITICAL
- **影響範囲**: 
  - アプリケーションキー (`APP_KEY`) の漏洩
  - データベース認証情報 (`DB_USERNAME`, `DB_PASSWORD`)
  - Google API 秘密情報 (`GOOGLE_CLIENT_SECRET`, Refresh Token)
  - ソースコード全体と Git 履歴の公開
  <br>**※ 旧システムでも同様の問題が発生する可能性があります。**
- **リスク**: 
  - セッション/クッキーの復号によるなりすまし
  - データベースへの不正アクセス、ランサムウェア攻撃
  - Google API の不正利用によるコスト増大・アカウント停止
  - 技術的知財情報の流出による追加脆弱性の探索リスク
- **原因**: Nginx が隠しファイルへのアクセス制御を実装していない、`.env` が `.gitignore` に未登録。
- **対策（短期）**: 
  - `php artisan key:generate` で `APP_KEY` 再生成
  - Google の Secret と Refresh Token を無効化・再発行
  - `DB_PASSWORD` を即時変更
  - Nginx で隠しファイルをブロック（`location ~ /\.` { deny all; return 404; }`）
  - `.env` を `.gitignore` に追加し、履歴から削除（`git rm --cached .env`）

#### 2. `laravel.log` による顧客個人情報流出
- **重大度**: CRITICAL
- **影響範囲**: 
  - ログ容量 7.2GB（2022/10 〜 2025/06）
  - 474MB（約 6.6%）が外部 IP `212.86.126.157`（ボットネット）に取得
  - 直接影響したユーザー 34 名（管理者 28 名、一般会員 5 名、運用管理者 1 名、テストアカウント 1 名）
  - 漏洩情報: 氏名、メールアドレス、bcrypt ハッシュ化パスワード、電話番号一部、アカウントステータス
  <br>**※ 旧システムでも同様の問題が発生する可能性があります。**
- **リスク**: 
  - 高性能マシンや hashcat でパスワードクラックの可能性
  - パスワード未変更ユーザーが多く、クレデンシャル流出リスクが高い
  - フィッシング攻撃の標的になる可能性
  - ブランドイメージと法的リスク（個人情報保護法）
- **原因**: Laravel が例外時にクエリパラメータ（バインド値）を自動記録し、`laravel.log` が公開ディレクトリに配置されていた。
- **対策（短期）**: 
  - `laravel.log` を公開領域外へ移動、もしくは削除後安全にバックアップ
  - 影響ユーザーへ即時パスワードリセットと通知メール送付
  - `storage/logs/` を `.gitignore` に追加

#### 3. マルウェア永続化（Malware Persistence）
- **重大度**: CRITICAL
- **影響範囲**: 
  - `/var/tmp/` 配下に ELF バイナリやシェルスクリプトが多数配置
  - `www` ユーザーの crontab にマルウェア実行タスクが登録（例: `@daily /var/tmp/6f2148e5/./51dc50c6`）
- **タイムライン**: 
  - 2026/01/27 初回侵入（`/var/tmp/5a118aba/` 作成）
  - 2026/03/10 新規フォルダ作成
  - 2026/03/12 ローダー更新
  - 2026/03/14 サーバ再起動後も cron が毎分実行を試行、パスが不存在のため実行失敗
- **現在のデータベース安全性**: 
  - バックドアアカウントなし、`root` は `auth_socket` 認証のみ
  <br>**※ 旧システムでも同様の問題が発生する可能性があります。**
- **リスク**: 
  - `www` 権限で OS の最高権限を取得可能
  - 6 週間にわたる活動期間中の不明な操作（データ抽出、バックドア設置）
- **原因**: 漏洩した `.env` から取得した DB 接続情報で攻撃者が権限昇格、crontab へ永続化タスクを設定。
- **対策（短期）**: 
  - マルウェアファイルを安全な外部ストレージへバックアップ後完全削除
  - `www` ユーザーの crontab を全削除し、信頼できるタスクのみ再作成
  - システムログ・ファイルシステムのフォレンジック調査

### V. 再発防止策 (PREVENTATIVE MEASURES)

1. **最小権限の原則 (Least Privilege)**:
   - **サーバ管理**: `root` アカウントでの SSH ログインを絶対禁止。開発者は個人アカウントで `sudo` を使用。
   - **DB 管理**: アプリケーション用 DB ユーザーは必要最低限の権限のみ付与。
2. **安全な構成基準**:
   - **プロジェクト構成**: Web サーバの Document Root は必ず `/public` に設定し、機密ファイルへの直接アクセスを防止。
   - **シークレット管理**: `.env` 等機密ファイルは Git 管理から除外し、Production サーバ上で厳格な読み取り権限を設定。
3. **リアルタイム監視 & アラート**:
   - **リソース監視**: CPU/RAM の異常増加を検知する監視システムを導入。
   - **ログイン通知**: SSH 成功時や `fail2ban` がブロックした IP があるたびに Slack/Telegram へ自動通知。
